# nvcodec: match CV-CUDA quality in the Lanczos preset

## Summary

Stacked on #41. The Lanczos preset now generates Lanczos-3 coefficients that follow CV-CUDA HQResize, replacing the GStreamer resampler's default Lanczos-2. The tiled kernel is restructured so the wider filter costs no extra GPU time or VRAM. On the full camera archive at 720p this is +2.39 mean VMAF over #41, and +4.90 on fisheye cameras, within 0.01 of CV-CUDA.

## Key decisions

- Match CV-CUDA's filter definition instead of raising GStreamer's envelope to 3. In ablations, envelope 3 left a 0.15 VMAF gap to CV-CUDA; the CV-CUDA definition closed it.
- Keep the tiled, no-scratch design. CV-CUDA's full-size FP32 workspace costs about 168 MiB more VRAM across 16 cameras.
- Write 32 output rows per block and stage weights in shared memory. Lanczos-3 in the unchanged kernel cost +41% GPU time; this version is 0.887× of #41 (geometric mean over 40 real geometries).
- Keep weights out of registers. A 16-register variant had a better geometric mean (0.863×) but a worse worst case (1.056× vs 1.019× of #41). The rule set before measuring picks the lowest worst-case ratio.
- Reject coefficient tables whose offsets decrease or run outside the plane, because the kernel derives each block's source span from the first and last offsets.
- Test against an independent analytic implementation of the filter rather than against the element's own tables.

## Verification

- `elements_cudakernel` passes 5 of 5 checks. The new oracle fails #41's Lanczos-2 output.
- Output is byte-identical to the frozen experiment build on 40 archive segments. One segment showed a one-off 2-frame difference that 4 reruns did not reproduce.
- compute-sanitizer memcheck, racecheck, synccheck and initcheck report 0 errors on 4 clips through the pipeline harness. libcheck cannot run under compute-sanitizer in the test container.
- Full-archive VMAF, the resource tests and the soak tests were run on the frozen build, which produces identical output. Results are in the PR description.

- Look into the one-off 2-frame output difference if it shows up again.
